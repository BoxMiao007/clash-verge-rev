# 0001 - 下载测速采用 GLOBAL 专用通道与限时下载

mihomo 没有按节点测带宽的 API(延迟端点只返回 TTFB),下载测速必须让真实流量经被测节点。决定:配置生成时注入一个仅绑定 127.0.0.1 的专用 mixed listener(`proxy: GLOBAL`);测速命令按「`PUT /proxies/GLOBAL` 切到被测节点 → 从专用端口发起限时下载 → 恢复 GLOBAL」执行,不触碰任何用户分组的选择。这样正确性不依赖规则路由,嵌套子组与 provider 节点也能测;代价是多占一个本地端口,且 global 模式用户在测速窗口内流量会被波及。listener 绑 GLOBAL 需实测验证;若不可行,回退为「切换被测分组 + /connections 链路校验」。

## Considered Options

- Cloudflare speed 端点作为下载源:大小可控,但易被 403/风控拦截,节点间结果不可比,弃用。
- 完整下载固定文件:结果更稳,但每节点消耗整份文件(~200MB),整组测速流量不可接受。
- 切换被测分组 + mixed port 下载:零配置管线改动,但嵌套子组在主组未指向它时会静默测到别的节点的速度,只能靠 /connections 校验降级为报错,该类分组实际不可用,且需额外的测速竞争中止逻辑。
