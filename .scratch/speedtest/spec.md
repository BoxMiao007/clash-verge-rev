# Spec: 节点下载测速

Status: ready-for-agent

领域词汇见根目录 `GLOSSARY.md`,路由机制决策见 `docs/adr/0001-download-speedtest-via-global-listener.md`。

## Problem Statement

用户在 Clash Verge Rev 里只能看到节点的延迟,看不到带宽。高延迟低带宽(中转线路、高峰拥堵)的节点无法甄别,选节点只能靠猜。上游维护者已确认扩展脚本/扩展配置无法实现此功能(延迟属于隐藏元数据,不写入配置 YAML),必须修改源码。

## Solution

在延迟测试旁新增「下载速度」测量:

- 分组头部提供整组测速按钮,组内节点逐个串行测量,每完成一个立即更新显示;
- 单个节点可通过悬停按钮单独测量;
- 节点项上延迟与下载速度并列常驻展示;
- 排序功能新增「下载速度」档;
- 设置中可自定义测速 URL 与测速时长。

测速不改变用户对任何分组的选择(经由 GLOBAL 专用通道,见 ADR-0001)。

## User Stories

1. 作为用户,我想一键测量整组节点的下载速度,以便找出真正快的节点而不只是延迟低的节点。
2. 作为用户,我想悬停单个节点单独测它的下载速度,以便快速验证某个感兴趣节点。
3. 作为用户,我想在节点项上同时看到延迟和下载速度,以便综合判断节点质量。
4. 作为用户,我想把节点按下载速度排序,以便最快的节点排最前。
5. 作为用户,我想测速不切换我的分组选择,以便测速期间正常上网不受打扰。
6. 作为用户,我想在设置里自定义测速 URL,以便默认测试文件不可用时换一个。
7. 作为用户,我想在设置里调整测速时长,以便在结果稳定性与流量消耗之间权衡。
8. 作为用户,我想整组测速时每完成一个节点就立即更新显示,以便了解进度与中间结果。
9. 作为用户,我想看到正在测速的节点显示测量中状态,以便知道它正在被测量。
10. 作为用户,我想测速失败的节点明确显示失败状态(区别于未测试与测量中),以便定位问题。
11. 作为用户,我想下载速度以人类可读单位展示(KB/s、MB/s 自适应),以便直观比较。
12. 作为用户,我想速度结果在短时间内保留并过期(与延迟行为一致),以便不必反复重测就能切换排序查看。
13. 作为用户,我想随时重新测量某个节点,以便刷新其过期结果。
14. 作为用户,我想 provider 加载的节点也能测速,以便统一对待所有节点。
15. 作为用户,我想排序档的选择被记住(与现有排序偏好一致),以便下次打开仍是我的偏好。
16. 作为多语言用户,我想新增文案覆盖各语言文件,以便界面不出现缺译。
17. 作为用户,我想整组测速可以随时再次触发,以便结果过期后刷新全组。
18. 作为用户,我想速度与延迟用同一套状态语义(未测试/测量中/超时/失败/有结果),以便理解成本为零。
19. 作为用户,我想分组卡片视图与列表视图都有测速入口,以便两种视图下功能一致。
20. 作为用户,我想默认参数开箱即用(默认测试文件与 5 秒窗口),以便不配置也能直接用。

## Implementation Decisions

- **测量机制(ADR-0001)**:配置生成时注入一个仅绑定 127.0.0.1 的专用 mixed listener,`proxy` 字段绑定为 GLOBAL;测速命令按「PUT GLOBAL 到被测节点 → 从专用端口发起限时下载 → 恢复 GLOBAL」执行。不触碰用户分组选择,不依赖规则路由,嵌套子组与 provider 节点均可测。此机制需以 spike 实测验证,是实现的第一个任务;若不可行,回退为「切换被测分组 + /connections 链路校验」方案(该回退方案下需补充测速竞争中止逻辑)。
- **测量方法**:限时下载求均值——GET 下载测试文件,达到测速窗口后中断,速度 = 已下载字节 ÷ 实际用时。默认测试文件为 googlechrome.dmg,默认测速窗口 5 秒。不设字节上限(时间已封顶)。
- **后端**:新增单节点命令,封装切换→下载→恢复全过程;Mihomo REST 直连(读当前 GLOBAL、PUT 切换/恢复),不改动外部插件 tauri-plugin-mihomo;HTTP 客户端复用 workspace 既有 reqwest。恢复 GLOBAL 失败只记日志,不向用户报错。
- **前端状态管理**:新建 SpeedManager,完全仿照 DelayManager:内存 Map 缓存 + 30 分钟 TTL 过期、同一套测量状态机(未测试/测量中/超时/失败/有结果)、监听通知与批量合并。整组测速由前端串行调度逐个调用命令(切换互斥,无并发),逐个完成即通知。
- **设置项**:两项——测速 URL、测速时长(秒)。仿照现有「默认测试链接 + 默认延迟超时」的成对模式,存入 verge 配置,放在同一设置弹窗。
- **UI 入口**:分组头部(列表视图与卡片视图)延迟按钮旁新增整组测速按钮;节点项悬停区新增单项测速按钮;节点项右侧延迟数值旁并列常驻速度数值,各自着色,速度用紧凑格式(MB/s 一位小数、KB/s 整数)。
- **排序**:排序档循环新增「下载速度」(降序,越大越前),无结果节点排最后;排序偏好沿用现有持久化机制。
- **词汇**:界面文案与文档使用「下载速度/速度测试」,避免用裸「测速」指速度功能(现有 UI 中裸「测速」按钮实际是延迟测试)。
- **已知取舍**(记录于 ADR-0001):global 模式用户在测速窗口内流量会被波及;速度与延迟一样重启清零;多占用一个本地监听端口。

## Testing Decisions

- 好测试只测外部行为,不测实现细节:对 SpeedManager 只测其对外查询/订阅接口与状态转换,通过 mock 后端命令边界驱动;不测内部缓存结构。
- **唯一新接缝**:SpeedManager 与后端命令的边界。测试仿照现有 DelayManager 的测试先例(mock invoke 层),覆盖:整组串行调度顺序、状态机转换(未测试→测量中→有结果/失败)、TTL 过期后重测、监听通知。
- **纯函数直测**:速度单位格式化函数、速度排序比较函数,仿照现有延迟工具函数与排序钩子的测试先例。
- **Rust 侧**:速度计算(字节÷用时)等纯函数用内嵌测试(先例:后端各模块既有内嵌测试);切换/下载链路不做集成自动化测试——GLOBAL listener 可行性由 spike 实测覆盖,端到端行为以应用内人工验证兜底,不引入 mock HTTP server。

## Out of Scope

- 上传速度测量(机制留待后续,本 spec 仅下载)。
- 并发测速(同组切换互斥,串行是唯一正确形态)。
- 测速结果历史趋势、图表、定时自动测速。
- 设置项仅 URL 与时长两项;总超时、字节上限、并发数、专用端口号均不作为设置项。
- 独立测速页面或工具型窗口。

## Further Notes

- 流量预期:整组测速时每个节点消耗 ≈ 测速窗口 × 节点实际速度(快节点一个窗口几十 MB),功能说明/README 中应向用户说明。
- 上游同步:本功能不可避免触碰上游文件(设置弹窗、配置生成管线、verge 配置结构体),按仓库约定将上游文件改动压缩到最小、新逻辑尽量收在本 fork 新增模块中。
- 参考项目:faceair/clash-speedtest(默认测试文件与限时窗口参数来源)、KodeBarinn/mihomo-speedtest-rs(仅参考参数,其自行管理 mihomo 进程的模式不照搬)。
- 实现时遵循仓库 AGENTS.md:feat 分支开发、验证门(pnpm typecheck && pnpm test + cargo check)、合入后在 AGENTS.md 功能清单登记。
