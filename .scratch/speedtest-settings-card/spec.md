# Spec: 速度测试设置卡片(测速设置独立成卡 + 测速流量上限)

Status: ready-for-agent

领域词汇见根目录 `GLOSSARY.md`,测速机制见 `docs/adr/0001-download-speedtest-via-global-listener.md` 与 `.scratch/speedtest/spec.md`(本 spec 是该功能的后续迭代)。

## Problem Statement

下载测速(速度测试)功能上线后,它的两项设置(测速 URL、测速时长)埋在「设置 → Verge 基础 → 杂项」弹窗里,入口深、与其他无关设置混排,用户难以发现,未来新增测速设置也无处安放。同时,整组测速的流量消耗(每节点 ≈ 测速窗口 × 实际速度,快节点一个窗口几十 MB)完全由测速窗口单一参数决定,用户没有「限制单节点最多下载多少」的直接手段。

## Solution

设置页新增一张常驻「速度测试」卡片,右栏位于「Verge 基础」与「Verge 进阶」之间,承载:

- 测速 URL(从杂项弹窗挪入);
- 测速时长(从杂项弹窗挪入);
- 测速流量上限(新增):单节点单次测速允许下载的最大数据量,MB 计,达到即提前结束并按实际数据计速,默认不限。

杂项弹窗中原来的两项同步删除,速度测试设置自此只有一个入口。已有配置的升级用户无感迁移。

## User Stories

1. 作为用户,我想在设置页直接看到「速度测试」卡片,以便不用记住测速设置藏在哪个弹窗里。
2. 作为用户,我想在卡片里自定义测速 URL,以便默认测试文件不可用时换一个。
3. 作为用户,我想在卡片里调整测速时长,以便在结果稳定性与流量消耗之间权衡。
4. 作为用户,我想设置测速流量上限,以便主动控制测速(尤其整组测速)的流量消耗。
5. 作为用户,我想流量上限默认不限,以便不配置时功能行为与从前完全一致。
6. 作为用户,我想填 0 或留空表示不限,以便随时恢复默认行为而无需删除配置。
7. 作为用户,我想达到上限的节点提前结束测速并正常显示速度结果,以便受限结果与其他结果同质可比,无需理解新状态。
8. 作为用户,我想流量上限对单项测速与整组测速一致生效,以便两种入口行为可预期。
9. 作为用户,我想卡片上的设置改动即时生效,以便不用找「保存」按钮。
10. 作为用户,我想 URL 输入在失焦后才写入配置,以免输入过程中每敲一个字符都落一次盘。
11. 作为用户,我想非法输入(超范围、非整数)被自动归一,以免坏配置悄悄生效。
12. 作为用户,我想速度测试设置只有一个入口,以免两处设置各自改、互相同步不了。
13. 作为用户,我想设置项带说明(tooltip/占位符),以便不看文档就理解「留空用默认值」「上限提前结束」等语义。
14. 作为已有配置的升级用户,我想原来的测速 URL 与时长设置原样保留生效,以便升级无感。
15. 作为多语言用户,我想卡片标题与新设置项文案覆盖全部语言文件,以便界面不出现缺译。

## Implementation Decisions

- **卡片接入**:新建独立设置卡片组件(新文件接入,减少对上游文件的改动),挂在设置页右栏「Verge 基础」与「Verge 进阶」之间;卡片标题「速度测试」。
- **卡片条目与保存**:条目沿用既有 GuardState 卡片模式即时保存;URL 为自由文本,输入过程只更新本地态,失焦时才写配置。时长输入沿用既有即时夹取。
- **旧入口**:杂项弹窗删除测速 URL 与测速时长两项(均为本 fork 既有增量,删除同时缩小上游文件改动面);延迟测试相关条目不动。
- **配置**:新增 `default_speedtest_max_mb`(MB 为单位);既有 `default_speedtest_url` / `default_speedtest_duration` 键名与语义不变,老用户已存值直接生效。
- **解析与界限单一来源**:上限解析/夹取与既有 URL、时长一样收在速度工具模块——0/未配置/非法(负数、非整数、越界)一律视为不限;1–1024 MB 为合法区间。Rust 侧持同一份界限做服务端校验(先例:测速时长两处同步的既有约定)。
- **后端截断**:单节点测速命令增加可选的字节上限参数(前端由 MB 配置换算);下载循环内已收字节达到上限即提前结束,速度 = 已下载字节 ÷ 实际用时;不传或 0 不限,行为与现状完全一致。截断结果不引入新的测量状态,测量状态五态不变。
- **前端透传**:SpeedManager 调用链(URL、时长、上限)单项与整组一致透传;命令参数带默认值,既有调用与测试向后兼容。
- **词汇**:界面文案沿用「速度测试」家族;GLOSSARY 增补「测速流量上限」词条。
- **文档**:原测速 spec 的「设置项仅 URL 与时长两项」「字节上限不作为设置项」决定由本 spec 推翻并留痕;AGENTS.md 功能清单中「节点下载测速」的关键文件/入口描述随合入更新。

## Testing Decisions

- 好测试只测外部行为,不测实现细节。本次新逻辑集中在上限的解析/夹取纯函数,直测即可,先例为速度工具模块现有的 resolve/clamp 用例。
- Rust 侧:界限校验纯函数用内嵌测试(先例:速度计算纯函数的既有内嵌测试);下载截断循环不做集成自动化——仓库约定不引入 mock HTTP server,端到端行为以应用内人工验证兜底(截断 + 计速 + GLOBAL 恢复不受影响)。
- **零新接缝**:全部复用既有接缝(速度工具纯函数直测、后端命令纯函数内嵌测试);SpeedManager 与后端命令边界的既有 mock 测试因参数向后兼容而不需改动。

## Out of Scope

- 定时自动测速(本轮讨论中评估过,明确不做)。
- 速度结果保留时长(TTL)设置化。
- 截断结果的「受限」标记或任何新展示状态。
- 总超时、并发数、专用端口号设置化。
- 上传速度测量。
- 卡片内「恢复默认」按钮(填 0 即不限,时长/URL 留空即默认,无需按钮)。

## Further Notes

- 流量预期:流量上限给了用户主动控流的手段,与原 spec「流量预期」注记互补;上限很小时(如 1 MB)慢启动节点结果偏保守,属已知取舍,由设置项 tooltip 说明「提前达到上限会提前结束」。
- 上游同步:仍不可避免触碰上游文件(设置页布局、杂项弹窗、verge 配置结构体),新逻辑尽量收在本 fork 新增模块,卡片本体为新文件。
- 实现遵循仓库 AGENTS.md:`feat/speedtest-settings-card` 分支开发,验证门 `pnpm typecheck && pnpm test` + `cargo check`。
