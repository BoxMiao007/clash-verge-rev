# 速度测试结果持久化 + 默认并行测速 + 更多测速链接

状态: 已确认方案,开发中(分支 `feat/speedtest-persist-parallel`)

## 目标

1. 每个节点/订阅的速度测试结果持久化保存;只能由手动测速更新;刷新页面、刷新订阅及其他刷新操作不得改变或去除。
2. 速度测试设置新增「并发测速数」:并发数即唯一的并行开关,1 = 逐个测速;不再单独提供并行开关。
3. 增加更多内置速度测试链接。

## 关键决策

- **结果归属**:按节点保存,同一节点跨分组共享;按订阅(profile)隔离,切订阅只看本订阅结果。
- **节点标识**:节点名 + 来源(provider 名 / core)。订阅刷新后名称与来源不变则沿用;改名/换源视为新节点。
- **生命周期**:只由手动测速更新;不提供手动清除按钮,重测即覆盖;测量中状态不落盘。结果不再 30 分钟自动过期。
- **孤儿清理**:仅在当前订阅节点集合成功加载后,清理该订阅内确实不再出现的旧结果;空集合(加载不完整)跳过。
- **存储**:前端 localStorage,键 `verge.speedtest.results:v1:<profileUid>`;重装/清 WebView 数据可能丢失(已知限制)。
- **展示**:速度值行内常驻;悬停显示测速时间。
- **并行**:配置生成时固定注入 8 个隐藏测速槽(selector 组 + 本地监听端口),运行时按设置并发数(1–8)取用;mihomo 走 listener `proxy:` 绑定槽组,meow 走 `IN-PORT` 规则引流。
- **单项测速**:同样走测速槽,不再切 GLOBAL;原 GLOBAL 专用通道保留为槽不可用/子组成员时的兜底。
- **默认值**:并发 4;并发数 1 即逐个测速。
- **测速链接**:内置预设 Cloudflare / Google / OVH / Hetzner / Cachefly / Tele2 + 自定义输入,选中写入现有 `default_speedtest_url`。

## 验收标准

- [ ] 手动测速后,刷新页面 / 刷新订阅 / 切换代理页,结果仍在,且显示测速时间。
- [ ] 同一节点在 A 组测过后,B 组也显示该结果并参与「按速度排序」。
- [ ] 切换订阅后只显示该订阅的结果;切回后结果还在。
- [ ] 订阅刷新删除某节点后,该节点的旧结果被清理;其它节点结果不受影响。
- [ ] 默认并行测速:整组测速并发执行(并发 4),明显快于串行;并发数设置生效。
- [ ] 单项测速不改变 GLOBAL 当前选择(global 模式下用户流量不被波及)。
- [ ] 设置页测速链接可从预设选择,也可自定义。
- [ ] `pnpm typecheck && pnpm test` 与 `src-tauri` 下 `cargo check` 通过。

## 工单拆分

1. 后端并行测速槽:注入 8 槽(listener + 隐藏 selector 组)、meow `IN-PORT` 引流、`speedtest_slot_ports` / `speedtest_node_via_slot` 命令、IVerge 新增 `default_speedtest_concurrency`。
2. 前端持久化:SpeedManager 按订阅作用域载入/持久化、节点标识、跨分组共享、孤儿清理、不自动过期;`use-speed-profile-scope` 接入代理页。
3. 前端并行调度:槽池、并发池、单项走槽、GLOBAL 兜底;设置项读取并行/并发。
4. 设置页与文案:并发数(唯一并行开关)、测速链接预设下拉;i18n(zh/en)。
5. 文档:ADR-0005、GLOSSARY 术语、本 spec。

## 已知限制

- 并行读数共享出口带宽,与串行结果不可直接横向比较;总流量约为并发数 × 窗口。
- provider 节点无法直接寻址,并行依赖槽组 `include-all`;子组成员走 GLOBAL 串行兜底。
- localStorage 存储:重装应用或清 WebView 数据可能丢失结果。
